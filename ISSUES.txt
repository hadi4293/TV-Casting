TV-Casting — بررسی کامل نواقص و اصلاحات
========================================
شاخه: fix/review-and-fixes
تاریخ: 2026-09-29

این فایل تمام نواقصی که در کد فعلی پیدا شد را فهرست می‌کند،
و برای هر کدام راه‌حل پیاده‌سازی‌شده را توضیح می‌دهد.


۱) فیچر «سازگاری خودکار کیفیت» در README هست ولی در کد نیست
--------------------------------------------------------------
مشکل: README ادعا می‌کند کیفیت بر اساس تأخیر اندازه‌گیری‌شده
خودکار تنظیم می‌شود، اما هیچ کدی برای اندازه‌گیری تأخیر یا
تغییر کیفیت وجود ندارد.
راه‌حل: کلاس LatencyMonitor اضافه شد که با پینگ‌های دوره‌ای
WebSocket تأخیر را می‌سنجد و کیفیت پیشنهادی را برمی‌گرداند.
فایل جدید: streaming/LatencyMonitor.kt


۲) فیچر «AirPlay 2 و Matter Casting» در README هست ولی در کد نیست
------------------------------------------------------------------
مشکل: README به هوک‌های AirPlay و Matter اشاره می‌کند که
پیاده‌سازی نشده‌اند.
راه‌حل: کلاس CastingHooks اضافه شد که اسکلت هوک‌ها را با
متدهای no-op و کامنت‌های راهنما فراهم می‌کند تا بعداً
قابل گسترش باشد.
فایل جدید: streaming/CastingHooks.kt


۳) کنترل‌های seek و volume در UI پیاده‌سازی نشده‌اند
----------------------------------------------------
مشکل: CastScreen فقط دکمه play/pause دارد. متدهای seek و
setVolume در ViewModel و Service وجود دارند ولی UI آن‌ها را
فراخوانی نمی‌کند.
راه‌حل: اسلایدر seek و اسلایدر volume به CastScreen اضافه شد.
فایل اصلاح‌شده: ui/CastScreen.kt


۴) Thread.sleep در نخ اصلی (main thread) صدا زده می‌شود
-------------------------------------------------------
مشکل: در StreamingService.startStreaming متد Thread.sleep(400)
روی نخ اصلی اجرا می‌شود که باعث ANR می‌شود.
راه‌حل: sleep به یک coroutine با Dispatchers.IO منتقل شد.
فایل اصلاح‌شده: streaming/StreamingService.kt


۵) گواهی خودامضا در هر بار استارت دوباره ساخته می‌شود
----------------------------------------------------
مشکل: CertUtils.generate در هر startStreaming صدا زده می‌شود
و کلید RSA 2048 بیتی تولید می‌کند — کند و بی‌ثبات.
راه‌حل: گواهی یک‌بار در init سرویس ساخته و کش می‌شود.
فایل اصلاح‌شده: streaming/StreamingService.kt


۶) هیچ مدیریت خطایی در UI نیست
------------------------------
مشکل: کلاس Error در StreamingState تعریف شده ولی هیچ‌جا
set نمی‌شود و UI پیامی نشان نمی‌دهد.
راه‌حل: مدیریت try/catch در startStreaming اضافه شد که
StreamingState.Error را set می‌کند، و CastScreen پیام خطا
را نمایش می‌دهد.
فایل‌های اصلاح‌شده: streaming/StreamingService.kt, ui/CastScreen.kt


۷) receiver.html هیچ نشانه‌ای از وضعیت اتصال به کاربر نمی‌دهد
------------------------------------------------------------
مشکل: صفحه گیرنده فقط یک اسپینر دارد و وقتی قطع می‌شود
یا خطا رخ می‌دهد، کاربر تلویزیون متوجه نمی‌شود.
راه‌حل: نشانگر وضعیت اتصال، شمارنده تلاش مجدد، و نمایش
خطا اضافه شد.
فایل اصلاح‌شده: assets/receiver.html


۸) ProGuard قوانین ناقص است
---------------------------
مشکل: قوانین فعلی فقط کلاس‌های nanohttpd و tvcasing را
نگه می‌دارد، اما BouncyCastle و Kotlin coroutines و
Compose reflection حذف می‌شوند.
راه‌حل: قوانین کامل‌تر برای BouncyCastle، coroutines،
Compose و reflection اضافه شد.
فایل اصلاح‌شده: proguard-rules.pro


۹) Workflow فقط APK دیباگ می‌سازد
--------------------------------
مشکل: README می‌گوید «signed-ready APK» ولی workflow فقط
assembleDebug اجرا می‌کند و signing را پیکربندی نمی‌کند.
راه‌حل: workflow به دو job تقسیم شد: یکی debug، یکی release
با استفاده از secrets برای keystore.
فایل اصلاح‌شده: .github/workflows/build-apk.yml


۱۰) هیچ تستی وجود ندارد
----------------------
مشکل: پروژه هیچ unit test یا instrumented test ندارد.
راه‌حل: یک تست واحد برای CertUtils و LatencyMonitor اضافه شد.
فایل جدید: app/src/test/.../CertUtilsTest.kt


۱۱) strings.xml ناقص است — چند متن هاردکد شده در UI
---------------------------------------------------
مشکل: CastScreen متن‌هایی مثل «Bağlı · HTTPS»، «Yayında»،
«Hata» را هاردکد کرده در حالی که strings.xml وجود دارد.
راه‌حل: تمام متن‌های UI به strings.xml منتقل شد.
فایل‌های اصلاح‌شده: res/values/strings.xml, ui/CastScreen.kt


۱۲) MainActivity سرویس را در onDestroy متوقف می‌کند
---------------------------------------------------
مشکل: onDestroy سرویس را صریحاً stop می‌کند، که باعث
قطع ناگهانی استریم هنگام چرخش صفحه یا تغییر کانفیگ می‌شود.
راه‌حل: توقف صریح حذف شد؛ سرویس با START_STICKY زنده می‌ماند.
فایل اصلاح‌شده: MainActivity.kt


۱۳) هیچ لاگ ساخت‌یافته‌ای برای دیباگ وجود ندارد
----------------------------------------------
مشکل: فقط Log.e در چند جا استفاده شده.
راه‌حل: یک wrapper لاگ ساده اضافه شد.
فایل جدید: util/AppLog.kt
